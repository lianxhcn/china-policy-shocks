我们整理了一个 **China Policy Shocks: [中国政策冲击数据库](https://lianxhcn.github.io/china-policy-shocks/)**。目的在于帮助大家寻找政策冲击、设计准自然实验、撰写政策评估论文。网站目前包含以下内容：

* **政策冲击数据库**：提供 Excel 和 CSV 下载，便于筛选、扩展和复用；
* **政策汇编**：按研究领域展示政策名称、年份、政策对象、处理组、冲击时间、数据合并键和识别风险；
* **方法说明**：说明一个政策冲击如何从政策文件转化为处理变量和研究设计；
* **政策卡片**：对中美贸易摩擦关税、中央生态环境保护督察、科创板注册制、药品集采等典型政策进行展开；
* **连享会资源**：整理 DID、IV、RDD、合成控制、论文复现等相关推文，方便读者继续学习方法和实操。

这个项目的目标不是罗列政策文件，而是帮助研究者判断：**一个政策能不能变成可识别、可合并、可解释的处理变量**。

## 1. 为什么要做这个网站？

很多做政策评估的研究者，并不缺政策文件。真正的困难在于：政策找到了，但不知道能不能写成论文。

常见问题包括：

* 政策是全面铺开的，不能只靠一个简单的 `Post` 识别效应；
* 试点城市本来就有更好的经济基础，不能直接和非试点城市比较；
* 政策对象是产品、药品、行业或金融机构，但研究数据是企业或城市；
* 文件发布时间、实施时间、名单公布时间和市场反应时间不一致；
* 处理组可以被企业主动选择进入，样本选择问题会影响识别。

这些问题不解决，回归模型写得再完整，也很难说明政策效应。

例如，很多研究都会写出类似模型：

$$
Y_{it}=\alpha+\beta(\operatorname{Treat}_{i}\times \operatorname{Post}_{t})+X_{it}'\gamma+\mu_{i}+\lambda_{t}+\varepsilon_{it}
$$

关键不在这个式子，而在 `Treat` 和 `Post` 是否成立。`Treat` 不是政策名称，`Post` 也不只是文件发布日期。它们需要根据政策对象、执行时间、数据层级和识别逻辑重新定义。

对于全面铺开的政策，也不是不能识别政策效应。更常见的做法是利用不同主体的政策前暴露程度差异：

$$
Y_{it}=\alpha+\beta(\operatorname{Exposure}_{i}\times \operatorname{Post}_{t})+X_{it}'\gamma+\mu_{i}+\lambda_{t}+\varepsilon_{it}
$$

其中，$\operatorname{Exposure}_{i}$ 可以是企业对美出口依赖度、污染排放强度、非标融资依赖度、碳排放强度、数据密集度或政策前产品结构。此时，识别来自政策后不同暴露主体之间的变化差异。

这正是我们做 China Policy Shocks 的原因：把政策文件、处理变量、数据接口和识别风险放在同一个框架里，让读者在选题阶段就能判断一个政策是否值得继续推进。

## 2. 一个政策冲击能不能用，先看四件事

判断一个政策是否适合做实证研究，不应只看它是不是重要政策，而应看它能不能落到数据和模型中。

- **政策事实是否清楚**
  - 政策事实包括发布机关、发布日期、实施日期、试点范围、适用对象、行业范围、产品清单和执行规则。
  - 事件研究需要明确事件日；多期 DID 需要明确不同地区或不同主体进入处理组的时间；产品层面冲击需要明确产品清单和编码体系。政策事实越清楚，后续变量构造越稳定。

- **处理组边界是否清楚**
  - 处理组不是「大概会受影响的人」，而是能在数据中被识别的样本。
  - 例如，药品集中带量采购的处理对象不是所有医药企业，而是特定通用名、特定规格、特定中选或未中选企业。中央生态环境保护督察的处理对象也不只是被督察省份，还可以进一步落到省内高污染企业、重点排污单位、被处罚企业或群众举报涉及企业。
  - 处理组越贴近政策执行对象，解释越清楚。

- **冲击时间是否清楚**

   政策冲击时间不一定等于文件发布日期。常见时间点包括：
   
   * 政策发布日；
   * 政策实施日；
   * 试点名单公布日；
   * 监管进驻日；
   * 企业被纳入名单日；
   * 市场开始反应的公告日。
   
   同一个政策可以有多个时间节点。使用哪个时间节点，取决于研究问题。

- **政策对象能否和数据合并**

  - 政策对象可能是地区、行业、产品、企业、金融机构、药品、学校、医院或个人。研究数据则可能是上市公司、工业企业、城市、区县、海关产品、专利、环保处罚、药品采购或招聘信息。
  - 只有当政策对象能和研究样本建立清楚的合并键时，政策才能进入实证研究。常见合并键包括城市代码、企业代码、行业代码、HS 编码、药品编码、股票代码和统一社会信用代码。

## 4. 从政策文件到处理变量

政策文件不能直接进入回归。真正的研究设计发生在政策对象和数据观测单位之间的映射过程中。

如果政策对象和研究样本不在同一层级，通常需要构造暴露度：

$$
\operatorname{Exposure}_{i}=\sum_{k} s_{ik,0}\operatorname{Shock}_{k}
$$

其中，$k$ 可以是产品、市场、行业、药品、银行或地区；$s_{ik,0}$ 是政策前权重；$\operatorname{Shock}_{k}$ 是政策在对象 $k$ 上的强度。使用政策前权重，是为了避免政策后调整行为反过来影响处理变量。

这种思路在很多政策中都很常见：

* 中美关税可以通过政策前出口产品结构构造企业关税暴露度；
* 环保督察可以通过督察进驻和企业污染暴露构造处理强度；
* 资管新规可以通过企业政策前非标融资依赖度构造暴露度；
* 药品集采可以通过企业政策前相关药品收入占比构造暴露度；
* 数据安全和个人信息保护政策可以通过企业数据密集度构造暴露度。

这一步决定了政策是否真正变成可估计的研究设计。

## 5. 四个示范政策

网站目前已经对若干政策做了详情卡片。下面列出四个示范。

### 5.1 中美贸易摩擦 301 关税清单

这个政策的优势是冲击落在产品层面。研究者可以把 USTR 关税清单和企业政策前出口产品结构连接起来，构造企业层面的关税暴露度：

$$
\operatorname{Exposure}_{i}=\sum_{p} s_{ip,0}\operatorname{Tariff}_{p}
$$

其中，$s_{ip,0}$ 是企业 $i$ 在政策前产品 $p$ 的出口份额，$\operatorname{Tariff}_{p}$ 是产品 $p$ 面临的新增关税税率或是否进入清单。

这个例子说明，全国性外部冲击可以通过产品清单和政策前贸易结构，转化为企业层面的连续处理强度。

### 5.2 中央生态环境保护督察

中央生态环境保护督察具有分批进驻特征，适合多期 DID。但只用「省份是否被督察」作为处理变量仍然偏粗。

更细的设定是把督察进驻和企业污染暴露结合起来：

$$
\operatorname{Treat}_{it}=\operatorname{Inspect}_{pt}\times \operatorname{Polluting}_{i}
$$

其中，$\operatorname{Inspect}_{pt}$ 表示省份 $p$ 在年份 $t$ 是否处于督察冲击下，$\operatorname{Polluting}_{i}$ 可以由高污染行业、重点排污单位、排污许可或历史环保处罚定义。

这个例子说明，同一个政策可以有多层处理变量。省份进驻、城市执法、企业污染暴露和企业处罚事件，对应不同研究问题。

### 5.3 科创板并试点注册制

科创板注册制是资本市场制度改革的重要冲击，但实际进入科创板上市的企业本身具有明显选择性。能否上市受到企业质量、行业前景、中介机构能力和监管审核影响。

更合适的做法是围绕政策前可识别的潜在受益企业构造处理组，例如根据政策前行业属性、研发强度、专利数量、高新技术企业身份或拟上市辅导信息识别：

$$
Y_{it}=\alpha+\beta(\operatorname{Eligible}_{i}\times \operatorname{Post}_{t})+X_{it}'\gamma+\mu_{i}+\lambda_{t}+\varepsilon_{it}
$$

这个例子说明，制度冲击不等于实际处理身份。处理组应尽量定义为政策前可识别的潜在受影响主体。

### 5.4 国家组织药品集中带量采购

药品集采的政策对象非常具体，涉及药品、企业和试点城市。不能把所有医药企业简单设为处理组。

如果有药品-城市-时间层面数据，可以使用三重差分：

$$
Y_{dct}=\alpha+\beta(\operatorname{Included}_{d}\times \operatorname{PilotCity}_{c}\times \operatorname{Post}_{t})+\mu_{dc}+\lambda_{ct}+\eta_{dt}+\varepsilon_{dct}
$$

其中，$d$ 是药品，$c$ 是城市。这个模型同时利用药品是否纳入、城市是否试点和政策前后变化。

这个例子说明，政策对象越具体，处理变量越应下沉到产品层面；企业层面研究最好使用政策前产品收入占比构造暴露度。
## 6. 如何使用和持续维护这个政策冲击库？

政策冲击库不是一次性清单，而是一个需要持续维护的研究工具。政策会继续更新，已有政策的官方来源需要补充，代表性论文会不断增加，处理变量也会随着数据可得性变化而调整。因此，静态推文适合解释方法和引导读者进入问题，网站则更适合承载数据库、政策卡片和扩展资源。

本项目采用 GitHub + Quarto + GitHub Pages 维护，主要考虑有四点：

* Excel 和 CSV 可以直接下载，便于读者筛选、修改和复用；
* Markdown / HTML 附录便于在线浏览和页内检索；
* 每次更新都有版本记录，方便追踪修改过程；
* 读者可以通过 GitHub issue 提交政策线索、修正建议和代表性论文。

项目主页：https://lianxhcn.github.io/china-policy-shocks/

GitHub 仓库：https://github.com/lianxhcn/china-policy-shocks

读者可以按自己的研究阶段使用这个网站。如果正在寻找论文选题，可以先看「政策汇编」页面，按领域浏览政策冲击，例如国际贸易、金融市场、环境治理、数字经济、财税政策、医疗教育劳动等。如果已经有大致方向，可以重点查看「处理组定义」「冲击时间」「数据合并键」「推荐方法」和「识别风险」等字段，判断这个政策能否进入自己的研究设计。如果正在设计模型，可以看「政策卡片」页面，参考几个示范政策如何从政策事实走到处理变量。如果需要继续学习 DID、IV、RDD、合成控制、事件研究或论文复现，可以看「连享会资源」页面，从政策冲击进一步进入方法学习。

当前版本仍是初版，后续会继续补充更多 A 类政策卡片、每条政策对应的代表性论文、政策冲击和可用数据的匹配说明，以及 Stata / Python 最小示例。后续也会考虑增加按方法筛选的索引，如多期 DID、DDD、事件研究、暴露度设计、shift-share 等，方便读者从研究方法反向查找合适的政策冲击。

我们也欢迎读者通过 GitHub 提交新政策、修正错误或补充代表性论文。这个数据库的价值不只在于已有条目，更在于它可以随着政策变化、数据开放和研究积累不断更新。

## 7. 小结

一个好的政策冲击，应当能够说清楚政策事实、处理组边界、冲击时间和数据合并键；否则，它更适合作为研究背景，而不是识别依据。

China Policy Shocks 的作用，是把这些判断前置，帮助研究者在选题阶段先筛掉「看起来重要、但难以识别」的政策，再集中精力打磨真正可用的研究设计。
